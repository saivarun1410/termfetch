# Termfetch launch plan

This plan is designed for the first repeatable milestone: 10 real users, five
publicly shared cards, and 10–25 relevant GitHub stars. Treat those as targets,
not guarantees. The baseline on 15 August 2026 was zero stars and zero forks.

## Positioning

Lead with the result, not the package format:

> Turn your GitHub profile into a neofetch-style terminal card in one command.

The supporting proof points are a custom photo, live GitHub statistics, a
self-contained SVG, six themes, no image service at view time, and MIT licensing.

## Before launch

- Use `assets/termfetch-demo.mp4` for the launch post and keep
  `assets/social-preview.png` ready for follow-ups.
- Temporarily set the X bio to `Building termfetch — neofetch-style GitHub profile cards`.
- Put `https://github.com/saivarun1410/termfetch` in the X profile website field.
- Confirm that the GitHub repository social preview uses `assets/social-preview.png`.
- Ask five developers to install the package and send honest feedback. Ask for a
  card or bug report, not a courtesy star.
- Spend 20–30 minutes leaving useful, link-free replies on current Python,
  open-source, GitHub README, terminal, and CLI conversations.

## Launch window

The first recommended test is Tuesday, 18 August 2026 at 9:00 PM IST. Post only
when there is time to answer every genuine response for the next 60–90 minutes.
Pin the launch post after publishing it.

1. Publish the launch post from `x-posts.md` with the MP4.
2. Immediately add replies 1 and 2 as a short thread.
3. Send the post privately to the five testers; do not ask for coordinated or
   artificial engagement.
4. Answer questions with specific help. Ask people who generated a card to
   share it, then repost their result with a personal comment.
5. Record the first-hour and 24-hour numbers in the table below.

## Seven-day cadence

| Day | Post | Asset | Goal |
| --- | --- | --- | --- |
| 1 | Launch and installation thread | `assets/termfetch-demo.mp4` | Repository visits and first users |
| 2 | Theme choice | `assets/theme-gallery.png` | Replies and preference data |
| 3 | How the self-contained SVG works | `assets/social-preview.png` | Technical credibility and bookmarks |
| 4 | First community card | User's card, with permission | Social proof |
| 5 | Feature poll | No media required | Product feedback |
| 6 | Before/after profile | Profile screenshots | Demonstrate the outcome |
| 7 | Results and next release | Best card from the week | Close the loop |

Do not repeat the same link and copy every day. Every follow-up should teach,
show, ask, or celebrate something new.

## Adjacent distribution

Use the prepared copy in `x-posts.md` only where self-promotion is allowed:

- Show HN after the X post has produced at least one external example.
- Relevant Python, open-source, command-line, and GitHub-profile communities.
- A short LinkedIn build story from the creator account.
- Developer Discord or Slack showcase channels where you already participate.

Do not mass-DM people, buy engagement, use follow-for-follow groups, or attach
unrelated trending hashtags.

## Measurement

Check X post analytics and GitHub's Insights → Traffic view at one hour, 24
hours, and seven days.

| Checkpoint | Impressions | Video views | Link clicks | Repo visitors | Stars | Installs/cards shared |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 hour |  |  |  |  |  |  |
| 24 hours |  |  |  |  |  |  |
| 7 days |  |  |  |  |  |  |

Decision rules:

- Many impressions but few profile or link clicks: strengthen the opening line
  and show the finished card earlier.
- Link clicks but few installs: shorten the README path to the first successful render.
- Installs but no shared cards: make configuration help and the showcase more visible.
- A post format performs at least twice as well as the others: reuse its structure
  with a new example rather than reposting identical copy.
